Mission Statement

To build sovereign digital infrastructure that a single independent engineer can own outright — architecture, data, and identity — rather than rent from platforms that can revoke access, sell the data, or disappear. Every service exists because an equivalent commercial product was judged inadequate, extractive, or untrustworthy: permit tracking not beholden to a vendor, terrain intelligence computed from physical law instead of licensed from a mapping monopoly, a browser that doesn't phone home, a community news outlet whose revenue stays in the community it serves.

The long-term purpose is broader than any one repository: a civic-technology substrate for a future where digital and physical infrastructure are the same infrastructure — where augmented and virtual reality are how people collaboratively build their own cities, and autonomous and robotic systems join that build-out under the same sovereign, auditable, provenance-tracked standards documented in this catalog.

Why It Exists

Independent verification, under duress, that a single person's engineering output can constitute a serious body of work — architected, tested, and documented to a standard that survives scrutiny, not a portfolio of toy projects.

How It's Built

Every repository is cross-referenced through a shared phase-tracking protocol, a common attribution and license standard, and a structural interconnection point (the XML intelligence pipeline) that every other service writes through.

What It Proves

Real, running, tested code, verified live this cycle: 179 passing Rust unit tests across three repositories, 223 passing Python tests, and — for the first time — the IP-forensics detection scanners actually run against live GitHub, npm, PyPI, crates.io, RubyGems, NuGet, and Docker Hub infrastructure, not just a mocked test suite.

Where It's Going

From desktop dashboards to a mixed-reality, physically-integrated civic build-out — the architecture in this catalog is the substrate that transition is built on top of, not a rewrite that transition will require.

Section IV — New This Edition
Live Verification & Operational Status

The prior edition catalogued what was built. This section catalogues what was actually run, against real infrastructure, and what that running surfaced — including problems found and fixed, stated plainly rather than smoothed over.

The ACT-009 Constraint

An org-level GitHub Actions setting has blocked every workflow in every repository in this estate from running at all since it was first identified — a platform policy issue, not a code defect, and one the estate's owner does not currently have access to resolve directly. Every workflow that used to run on GitHub's own runners has been failing at the runner-startup stage regardless of what the workflow does.

Rather than leave the estate without CI or a merge-readiness process, agents/estate_pipeline.py in the RoadMaps repository reimplements the equivalent stages as plain Python: real git operations, real local build/test/lint execution, real dependency-advisory queries against OSV.dev and the GitHub Advisory API, and a real readiness decision logged per pull request. It decides readiness; it does not click merge — that action is reserved by GitHub's own platform for a sanctioned, human-supervised path, by design.

IP-Forensics Live Smoke Test Verified

The detection scanners were run against real GitHub, npm, PyPI, crates.io, Docker Hub, and Hugging Face infrastructure for the first time. Found and fixed: a scoring-gate bug that would have let unverified findings through to draft accusation documents; registry search noise that returned unrelated real packages (including an official vendor SDK) as false "findings"; and a self-scan bug in the structural-similarity scanner that would have flagged this estate's own source code as infringing on itself. All four fixed with dedicated regression tests, verified against live data.

Registry Coverage Expanded Verified

RubyGems and NuGet added using the same exact-match probe pattern already proven safe for PyPI — no new false-positive surface introduced. Registry scanning now spans five package ecosystems plus GitHub code search, Docker Hub, and Hugging Face.

Sovereign-Canary Integrity Verified

A fabricated test artifact briefly touched local repository state during development of the AST candidate scanner. Traced end to end: confirmed it never reached the public violation log, because the script that writes there only ever reads from a separate, unaffected data source. Corrected forward with a documented commit rather than rewritten history.

Economic Policy Publication Verified

The Investor Priced Index (IPI) framework — an authored economic policy proposal, not a build item — published under CC BY 4.0 as a deliberate exception to this estate's default all-rights-reserved license, with an editorial note distinguishing cited, real economic literature from the proposal's own illustrative, unvalidated coefficients. Its core recirculation-rate math is additionally embedded as real, tested code in MacroHarder — narrowly: the calculator only, not the proposal's banking-regulation enforcement mechanisms, which no software here could implement without actual regulatory authority.

GitHub Code Search From Managed Sessions Known Limitation

GitHub's global code-search endpoint is not reachable from this estate's managed development sessions (a platform-side proxy restriction, distinct from ordinary rate limiting). A circuit breaker now detects this in under a second instead of retrying for twelve minutes every cycle. The registry, Docker Hub, and structural-similarity scanning legs are unaffected and run live on every cycle.

Vision — The Physical-Digital Merger

Every system in this catalog is architected as an API-first, headless service precisely because the interface layer is not the destination. The long-term plan remains a transition to augmented and virtual reality as the primary way people see and collaboratively build their own civic infrastructure — unchanged from the prior edition, and unaffected by anything reported on Page 4.

That transition requires the estate to include everyone in the build-out process, not just engineers with dashboard access. It also requires integrating autonomous and robotic systems into physical construction and maintenance under the same provenance, audit, and capability-gating standards already enforced in software. Solidarity Goggles remains the working name for that mixed-reality presentation layer — not built, and not claimed as built here; a direction, recorded honestly as one.

None of this requires the current architecture to be rewritten. It requires exactly what has been built and, this edition, actually run: sovereign data, capability-gated module boundaries, cryptographic provenance, and a phase-tracked roadmap that now includes a verified operational record, not just a design record.
